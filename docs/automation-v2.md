# 大一造园 · 自动交付试用版

2026-09-19。依据 `dayi_UI系统_V1.6_完整规范最终版.docx` 与 `DAYI_Workflow测试矩阵与评估表_V0.1_2026-09-19.docx` 实施。

## 本次实际完成

客户端维持一屏一步、39.9元一张方向图与三条建议。使用规范原始 dayi 标志资产。上传照片会先校正方向并压缩；订单使用独立访问密钥，刷新可恢复；结果图加载成功且三条建议齐全才显示完成。补齐微信咨询、收款码保存和结果保存入口。

后台新增真实图像 API 适配器与五阶段持久任务：理解现场 → 编辑方向图 → 保存图片 → 复核与建议 → 交付。任务存在数据库中，客户或管理员关闭页面不影响执行。每单最多两次出图；对不确定是否已经计费的超时请求停止自动重发。管理员核查供应商记录后，可在剩余额度内明确授权再试。

管理页支持实际到账确认、失败订单、测试订单、完整交付数量与到账金额；刷新登录凭证时重建 Authorization，修复原先重试仍带旧凭证的问题。新测试订单金额为0，不计入收入。

**当前后台与定时任务已部署，接单开关保持关闭。尚未配置真实模型密钥、未发生本版真实模型调用，也没有完成真实庭院质量验收。**

## 一次性开通

1. 打开网站的 `/dashboard/`，使用原有大一管理邮箱登录。
2. 在“一次性设置与上线测试”填写阿里云百炼密钥。地域须与服务地址一致。密钥通过管理员接口保存在加密 Vault，不返回客户端。
3. 分别上传毛坯、硬化、已有植物三类不同真实现场，选择方向与保留项，点击“自动跑一次测试”。会消耗模型账户额度，不收客户款。
4. 对照原图检查建筑、门窗、围墙、视角及保留项，确认结果符合大一标准后点击“已对照原院，核对通过”。不同现场及三个类别均通过后，才能开放客户接单。调整模型或核心参数会要求重新验证。
5. 客户接单前还应在真实手机上验收上传、付款返回、订单恢复、原图对照和保存结果，并完成实际图片质量测试。当前试用站仅大一本人可见。

日常接单：核对收款平台的**实际到账记录** → 点击确认 → 后台自动制作、复核、保存与交付。付款截图本身不是银行到账凭据。

## 与原测试矩阵的关系

本版先实现官方托管 Qwen 图像编辑接口，不要求本地显卡、ComfyUI 或常驻电脑。使用自然语言现场理解、图像编辑与视觉复核；未引入未经证明有必要的 Depth / Edge 控制。

默认图像模型为 `qwen-image-2.0-pro-2026-06-22`，视觉理解模型为 `qwen3-vl-plus`，均可在管理页调整。此选择旨在降低维护成本，**并未通过实际 A/B 测试证明它优于文档中的 Qwen-2511 或 Flux2**。原矩阵的双模型、参考图及多种子比较仍属于后续质量实验；本版不包含 Flux 适配器。后台已预留按风格读取参考图片路径，但管理页暂未提供参考图上传。

评分保留原矩阵的权重：结构25、需求15、景观15、大一风格15、真实10、克制5、图文一致5、后续承接5、效率5。结构等硬性检查不通过或模型表示不确定时，不因总分高而放行。自动视觉检查仍可能误判，首次真人核对不能以分数替代。

## 尚未完成的能力

- **支付到账全自动**：现有富掌柜收款码没有提供商户接口凭据。本版没有伪造支付回调；仍为人工确认到账。取得正式接口后需要验签、商户和金额核对、幂等通知及主动查单对账，才能替换这一步。
- **真实出图验收**：需有效模型密钥及额度、三类真实现场。没有用模拟图片冒充真实交付。
- **手机浏览器验收**：当前环境下载 Chromium 超时，真实浏览器脚本未成功运行。已完成页面结构与实际脚本逻辑测试，但不等同于手机视觉和点击验收。
- **二次付费产品**：29.9、199、499入口现为带订单号的咨询承接，不是独立自动支付与交付商品。
- **主动通知与退款**：客户通过订单链接查询；未接通微信主动通知和支付退款接口。异常订单保留，可由大一继续处理。
- **历史迁移**：原四笔记录保留；旧公开页面和旧订单查询仍兼容。旧公开结果桶没有批量迁移。本次私密试用版本不等于已经替换旧公开客户网站。

## 开发与维护

源码中的 `direction-feedback/config.mjs` 仅包含公开 Supabase 客户端标识，不含服务密钥。`supabase/functions/direction-feedback-api/index.ts` 使用 Supabase 自带服务环境密钥。Edge Function 的 `verify_jwt=false` 是为了容纳三个明确的认证通道：管理员经 Auth 验证、客户使用256位订单密钥、定时任务使用独立 Vault 秘钥；不是关闭应用层认证。

迁移依次为：`dayi_automation_v2.sql`、`dayi_service_permissions.sql`、`dayi_scheduler_v2.sql`。`dayi_claim_fix.sql` 是部署核验发现变量与表别名冲突后的修复记录；主迁移已经包含该修复。

本地检查：Node 22+。`node --test tests/workflow.test.mjs tests/frontend.test.mjs`。实际浏览器检查需安装 Playwright 与 Chromium，在项目根目录启动 `python -m http.server 8765 --bind 127.0.0.1 --directory direction-feedback`，再运行 `node tests/browser-qa.mjs`。

暂停新接单：管理页关闭接单开关。不会删除订单。密钥失效、余额不足、供应商限流和超时需在模型平台核对；不得为图省事清空任务检查点并无限重跑。
