# 客户端流程修复与验证 · 2026-09-20

## 先复现，再修改

修改前，用 Chromium 153 实际点击页面：首次选择“100㎡以上”会进入需求页；返回面积页，或者刷新面积页后，再次点击已选中的“100㎡以上”，页面仍停在面积页。该页没有下一步按钮。风格页使用同样的 change 自动跳转逻辑，存在相同断点。100㎡选项在后台枚举中有效；付款页和联系方式本身存在。

## 针对断点的修改

- 面积、风格页提供明确的下一步；选择只更新选择状态，不依赖计时器跳转。
- 返回和刷新保留选择；需求多选即时保存。
- 已创建但未提交的订单，刷新编辑页时保留编辑位置；修改的需求重新保存到原订单。
- 服务说明改为“确认后安排方向反馈”，与当前实际交付能力一致。
- 公司原始二维码、收款主体、39.9元价格、联系方式和付款凭证保留。

## 验证结果

`tests/client-flow.browser.mjs` 使用真实 Chromium、DOM 事件、图片解码和浏览器存储；受控接口用于测试网络失败与重复操作，无真实扣款。

390×844 与 1440×1000 两种尺寸均通过：5个面积选项、5个风格选项、返回重选、刷新恢复、空需求拦截、多选保存、确认摘要、付款页可达、原始二维码加载和下载、联系方式保存、凭证保存、网络失败重试、草稿修订保存、提交后刷新恢复、无横向溢出、无页面脚本异常。

另以真实浏览器走完整页面，浏览器请求通过运行环境网络转发到已部署接口，完成：上传原院 → 100㎡以上 → 需求 → 风格 → 说明 → 确认服务 → 付款信息 → 联系方式与测试凭证 → 提交 → 刷新恢复。数据库核对 checkout_stage=submitted，yard_size=100㎡以上，照片、联系方式和凭证均存在，payment_status=pending_verification。该笔记录已标为测试、金额0，不计入营收；没有实际银行扣款。

原有28项 Node 检查通过。客户支付应用内扫码付款和商户实际到账不属于这次浏览器模拟测试；仍需实际到账核对，自动出图服务状态没有因此改变。

## 运行浏览器回归
