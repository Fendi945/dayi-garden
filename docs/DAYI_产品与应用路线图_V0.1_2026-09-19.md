# DAYI 产品与应用路线图 V0.1

日期：2026-09-19  
状态：长期维护文档

## 0. 总目标

DAYI 不做“功能堆叠的软件集合”，而是逐步形成一个以自然语言为统一入口的个人智能工作台与庭院设计生产系统。

核心原则：

1. 把大一的判断力、审美、设计规则沉淀成系统，而不是把人绑在重复操作上。
2. 模型、API、节点、GPU、支付渠道等复杂度尽量隐藏在后台。
3. 客户只表达需求，大一工作台只呈现业务、判断、风险、结果与现金流。
4. 模型可替换，工作流和判断标准才是长期资产。
5. 先跑通最短商业闭环，再逐步增加复杂能力。
6. 每一个应用都应尽量形成可自动运行、可监控、可复盘的数据闭环。

## 1. 产品地图

### A. DAYI Garden｜庭院即时方案反馈

定位：第一把商业化利器，也是当前优先级最高的现金流产品。

目标流程：

客户上传真实庭院照片  
→ 输入需求  
→ 选择服务 / 支付  
→ 自动生成结构化设计需求  
→ AI 生成改造方向图  
→ 生成 3 条专业建议  
→ 客户查看结果  
→ 引导进入咨询 / 设计 / 施工陪跑

V1：
- 真实庭院照片上传
- 需求采集
- 支付确认
- 1 张可信方向图
- 3 条设计建议
- 订单状态
- 客户结果页

V1 不做：
- 多轮自由编辑
- 视频游历
- 无限风格选择
- 完整施工图
- 复杂图层编辑

成功标准：
- 客户无需学习任何 AI 工具
- 付款后能自动得到可理解的结果
- 结果能支撑后续 199 / 499 / 完整设计转化
- 大一不需要守在电脑前搬运图片

---

### B. DAYI Business Console｜业务后台 / 收银反馈系统

定位：不是 AI 模型控制台，而是大一的业务操作后台。

只呈现：
- 新订单
- 已付款 / 待付款
- 处理中 / 异常 / 已完成
- 客户需求摘要
- 结果预览
- 是否需要人工判断
- 退款 / 重做 / 升级服务
- 收入与转化数据

后台隐藏：
- 模型名称
- API 网站
- ComfyUI 节点
- GPU 参数
- Prompt 技术参数

原则：
**大一工作台负责决策，底层系统负责执行。**

---

### C. DAYI Garden Factory｜自动化图像生产工厂

定位：庭院即时反馈产品的后台生产引擎。

V1 固定任务：

真实庭院照片  
→ 视觉理解  
→ 结构保持  
→ DAYI Prompt  
→ DAYI 风格参考  
→ 图像编辑 / 生成模型  
→ 2–3 张候选  
→ 自动 / 半自动质量判断  
→ 高清处理  
→ 回传 Supabase  
→ 客户端展示

长期核心资产：
- DAYI Prompt System
- DAYI Reference Library
- DAYI Workflow
- 真实订单数据
- 质量评估体系
- 失败案例库

技术原则：
- 模型属于可替换渲染层
- 先验证质量，再优化成本
- Depth / Edge / ControlNet 只在结构漂移时加入
- 不为了节点多而增加复杂度

---

### D. DAYI Visual Editor｜自然语言图像编辑器

灵感来源：Compositor，但不复制一个完整 Photoshop。

目标：
客户或设计师直接说：
- “把右侧红枫换成腊梅”
- “池水不要这么蓝”
- “删掉这堆杂物”
- “保留房子，只改院子”
- “这块铺装换成老石条”

系统自动完成：
识别目标  
→ 生成 Mask  
→ 局部删除 / 重绘  
→ 匹配透视  
→ 匹配光线  
→ 合成  
→ 返回结果

优先能力：
1. Selection Engine
2. Mask Engine
3. Layer / Object Model
4. 局部 Inpainting
5. Remove Background
6. Content-Aware Fill
7. 色彩 / 明暗调整
8. 局部材质 / 植物替换

核心方向：
**把 Photoshop 工具语言隐藏掉，只保留自然语言。**

---

### E. DAYI Semantic Layers｜庭院语义图层系统

长期目标：AI 输出不再只是“扁平 JPG”，而是可控对象集合。

建议语义层：
- 建筑
- 围墙
- 门窗
- 天空
- 乔木
- 灌木
- 地被
- 草坪
- 铺装
- 水体
- 景石
- 家具
- 灯光
- 装饰
- 排水 / 工程约束

用户说：
“把这棵树换掉”

系统实际定位：
Tree_03  
→ Mask  
→ Replacement  
→ Relight  
→ Composite

这是从“AI 生图工具”走向“AI-native 庭院设计操作系统”的关键一步。

---

### F. DAYI Workbench｜大一工作台 / 个人智能操作系统

定位：所有业务、知识、决策和自动化的统一入口。

不是传统后台，也不是模型控制面板。

主要模块：
- 今日
- 灵感
- 项目
- 客户
- 订单
- 财务
- 内容
- 资料 / 数字资产
- 工作流
- 元认知 / 我的内核
- 自动化
- 风险与提醒

长期体验：
只需要自然语言表达：
“这个客户下一步怎么推进？”
“今天有哪些订单异常？”
“把这个想法归档到内容库。”
“把这张现场图生成三个庭院方向。”
“把本月现金流给我看一下。”

工作台负责理解意图并调度具体应用。

---

### G. DAYI Video Agent｜自动视频生产

目标：
素材上传  
→ 自动转录  
→ 内容重构  
→ 选取高价值片段  
→ 自动生成字幕  
→ 调整节奏  
→ 插入现场图 / 示意图  
→ 套用 DAYI 封面和字幕规范  
→ 导出短视频

原则：
- AI 不只是剪片，而是进行“内容重构”
- 保留大一的判断和语言风格
- 封面、字幕、节奏遵循固定品牌系统

现阶段：
先做半自动稳定流程，再逐步完全自动化。

---

### H. DAYI Finance OS｜AI 财务运营系统（内部实验）

首阶段只服务大一自己的公司。

目标：
- 银行流水导入 / 连接
- 自动分类
- 自动记账
- 对账
- 异常项确认
- 月度利润表
- 现金流
- 财务月报
- 发票 / 无票支出标记
- 风险提示

原则：
先把原来需要数小时的人工作业压缩到几分钟，再判断是否产品化。

## 3. 开发顺序

### Phase 0｜现在
目标：先跑通收费闭环。

优先：
1. DAYI Garden 客户端
2. 支付闭环
3. Business Console
4. 订单 / 状态 / 结果回传
5. DAYI Factory V1
6. 第一批真实订单验证

不做大而全。

### Phase 1｜方向图自动交付
目标：人工搬运接近 0。

- 自动结构化需求
- 自动 Prompt
- 自动生图
- 自动回传
- 基础质量检测
- 异常任务进入人工队列

### Phase 2｜自然语言局部修改
目标：解决“这张图大体对，但局部需要改”。

- SAM / segmentation
- Grounding / object detection
- 自动 Mask
- Inpainting
- 植物、铺装、水体、景石局部替换

### Phase 3｜语义图层
目标：从 JPG 生成进入可控编辑。

- 建筑 / 植物 / 铺装 / 水体等语义对象
- 锁定不可改变区域
- 单对象替换
- 多轮编辑历史

### Phase 4｜设计 Agent
目标：模型开始按照 DAYI 规则主动做方案推理。

- 场地问题识别
- 动线判断
- 排水风险
- 使用者需求冲突
- 维护成本
- 设计取舍
- 多方案比较

### Phase 5｜DAYI OS
目标：工作台成为统一操作层。

自然语言一句话调度：
客户 / 项目 / 财务 / 内容 / 设计 / 视频 / 网站 / 自动化。

## 4. 2026-09-19 Compositor 带来的新结论

Compositor 不适合直接作为 DAYI Windows / Web 应用基础，因为它高度依赖：
- SwiftUI
- AppKit
- Core Image
- Metal
- macOS 原生框架

但其架构非常值得借鉴。

重点研究：
- Layer Engine
- Mask Engine
- Selection Engine
- GPU Render Engine
- 非破坏性编辑
- 图像合成与 Adjustment Pipeline

不复制其 Photoshop 式 UI。

DAYI 的差异：
**Compositor：用户操作工具。  
DAYI：用户说结果，Agent 操作工具。**

未来可复用其 MIT 许可下允许借鉴 / 修改的代码与架构，但必须保留相应版权和许可声明。

## 7. 当前最高优先级

不是一次性把所有应用做出来。

当前唯一 P0：

**让一个陌生客户可以完成：
进入 → 上传 → 描述 → 付款 → 自动生成 → 看到结果。**

当这个闭环稳定后，再向 Visual Editor、Semantic Layers 与 DAYI OS 扩展。

这条路线同时服务两个目标：

1. 解放大一的重复劳动与搬运时间；
2. 把判断力、审美和设计经验逐步变成可复制的数字资产。
