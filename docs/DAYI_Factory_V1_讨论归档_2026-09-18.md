# DAYI Factory V1｜讨论归档
日期：2026-09-18

## 1. 当前项目目标
将「庭院改造方向反馈」从人工辅助交付，升级为可自动运行的图像生产流水线：

客户上传真实庭院照片与需求 → 付款 → 后台确认 → 自动生成专业提示词 → GPU 云端工作台执行生图 → 结果回传 Supabase → 客户端自动展示。

V1 只解决一个问题：
**真实庭院照片 → 1 张可信的改造方向图 + 3 条设计建议。**

不在 V1 同时加入局部修改、视频游历、多轮重绘、多风格并行等复杂能力。

## 2. 商业原则
1. 不把正式收费产品建立在“自动点击免费生图网页”上。
2. 技术上能用 ≠ 商业上可稳定、可授权地使用。
3. 产品核心不是某个模型，而是：
   - DAYI Prompt System
   - DAYI Reference Library
   - DAYI Render Workflow
4. 生产系统不依赖别人随时可能改变的社区镜像或私有模型。
5. 先验证图像质量，再优化基础设施与成本。
6. 优先追求：80 分以上质量 + 高稳定性 + 低人工干预，而不是偶发的极致效果。
7. 客户付费后后台可生成 2–3 张候选，最终只交付最佳 1 张，提高交付稳定性。

## 3. 仙宫云架构理解
仙宫云可视为“厂房 + 电”：
- GPU 云实例
- 镜像
- ComfyUI
- 模型 / 插件 / 工作流
- 实例开机、关机、销毁、GPU 释放

目标不是复制仙宫云，而是在其 GPU 基础设施上建立：
**DAYI-GARDEN-FACTORY-V1 私有镜像**

建议流程：
有任务 → 启动 GPU → 自动执行 → 回传结果 → 空闲后释放 GPU。

## 4. 自动化目标链路
客户前端
→ Supabase（订单/原图/需求/支付状态）
→ DAYI 任务调度器
→ GPU 实例
→ ComfyUI API
→ 自动上传原图
→ 注入 DAYI 提示词
→ 执行固定 workflow
→ 输出候选图
→ 选择最佳图
→ 上传 Supabase Storage
→ 回写 orders.result_a_path / advice_json
→ process_status = completed
→ 客户前端自动展示。

## 5. 已分析的参考工作流
文件：
《【完课赠送】室内草稿图一键彩平 仙宫云.json》

这套工作流不是简单的“模型 + 提示词”，而是一个成熟的双参考结构。

### 5.1 结构约束
上传平面图
→ LineartStandardPreprocessor
→ ControlNet
→ mistoLine_rank256.safetensors

关键参数：
- ControlNet strength ≈ 0.69
- start = 0
- end ≈ 0.70

作用：
保留原图线条与结构，避免模型完全重构空间。

### 5.2 风格参考
上传彩平风格参考图
→ IPAdapter Plus SDXL
→ CLIP-ViT-H-14-laion2B-s32B-b79K
→ ip-adapter-plus_sdxl_vit-h.safetensors

关键参数：
- IPAdapter weight ≈ 0.51
- strong style transfer
- concat
- V only

作用：
第一张图规定“结构”，第二张图规定“风格”。

### 5.3 自动视觉理解
参考图
→ Florence-2-large
→ more_detailed_caption
→ 自动生成 caption
→ 写入正向提示词

启示：
机器可以负责“识别图里有什么 / 风格是什么”，而 DAYI 系统负责“什么该保留、删除、增加”。

### 5.4 生图主链
底模：
SDXL通用大模型.safetensors

LoRA：
SDXL 室内/SDXL 室内彩平2.0.safetensors
- LoRA model strength ≈ 0.59
- clip strength = 1

采样：
- steps = 15
- CFG = 3
- sampler = euler_ancestral
- scheduler = normal
- denoise = 1
- batch = 3

核心公式：
**结构图 + 风格参考图 + 自动视觉描述 + 专用 LoRA → 3 张候选结果**

## 6. 对 DAYI Garden Workflow V1 的启发
庭院不能机械照搬室内彩平，但可以保留其逻辑：

### 输入
- 1 张真实庭院现场照片
- 院子面积
- 主要需求
- 风格方向
- 特别备注

### 输出
- 1 张庭院改造方向图
- 3 条设计建议

### 拟定生产链
1. 原图输入
2. 现场视觉理解
3. 结构保持
4. DAYI 设计提示词
5. 风格参考
6. 主图像模型
7. 一次生成 2–3 张候选
8. 质量筛选
9. 必要时轻量高清
10. 回传 Supabase

## 7. 结构保持的测试方向
真实庭院照片与平面图不同，应重点测试：
- Depth：保持空间深度、建筑体块
- Lineart / Canny：保持围墙、门窗、边界
- 原图 img2img：保持视角与整体摄影视角
- Depth + Lineart 双控制：仅在确认质量明显提升时采用

原则：
**不为了“节点多”而复杂化。删掉对结果贡献不明显的节点。**

## 8. DAYI Prompt System
客户原始表达不能直接交给模型。

后台要先做“大一翻译器”，把客户语言转成设计语言。

例如：
客户：
“想自然一点、喝茶、养猫、怕潮、低维护。”

系统转换：
- 保留原建筑、围墙、门窗和主要空间关系
- 控制硬化比例
- 形成清晰主通行路径
- 设置安静休息 / 品茶区域
- 植物选择兼顾宠物安全
- 靠墙留通风与排水带
- 控制植物密度和修剪量
- 避免景石、装饰、灯具堆砌
- 强调自然生长、光影与留白

模型是执行者，DAYI 的判断和取舍才是核心资产。

## 9. DAYI 结果验收标准（V1）
至少满足：
1. 建筑与围墙不乱改
2. 门窗、出入口关系基本保持
3. 透视不明显变形
4. 动线合理
5. 植物不廉价堆砌
6. 气质自然、克制、有留白
7. 不呈现明显“网红 AI 效果图”感
8. 改造结果能支撑后续 199 / 499 / 完整设计转化

## 10. 模型策略
不预先锁死某一个模型。

模型属于“可替换的渲染层”。

可测试：
- Qwen-Image-Edit / Qwen 图像系列
- 其他商业许可清晰的开源图像编辑模型
- 外部 API 作为高质量备选

OpenAI 的开放权重 gpt-oss 可作为：
- 需求理解
- 设计信息整理
- 提示词大脑
但不是本地生图模型。

视频模型（例如 MiniMax H3）放在第二阶段，用于：
**庭院方向图 → 5–10 秒动态游历**
不放入 V1 主链。

## 11. 系统分层
### A. 业务层
订单 / 支付 / 状态 / 存储 / 客户结果页

### B. 设计层
DAYI Prompt
DAYI 设计规则
参考图选择
3 条建议生成
质量判断

### C. 渲染层
ComfyUI
模型

GPU
高清处理

目标：
以后换模型，只替换 C 层，不重做整个产品。

**DAYI Prompt System + DAYI Reference Library + DAYI Workflow + 真实订单数据。**
